# Fitur chat bot (plugin)

Perilaku rinci setiap fitur plugin di chat bot (`plugin/`): `/context`, format balasan, tombol, perintah bawaan, akses tanpa pairing, typing dan reaksi, kutipan, lampiran, album, pengingat konteks.

Rincian ini dipindahkan apa adanya dari `CLAUDE.md` (tiket 261115094501). Rujukan `lihat "<judul bagian>"` yang tidak ada di berkas ini menunjuk ke bagian di berkas `docs/` lain; cari lewat daftar isi di `CLAUDE.md`.

## /context di chat bot (tiket 261112230304)

Pemilik mengetik `/context` di chat bot dan langsung mendapat sisa konteks sesi itu serta kuota akun, tanpa memakai giliran Claude. Isi dan formatnya sama persis dengan `/context` mirza-bots: `plugin/context-render.ts` adalah salinan `renderContext` dari `mirza-bots/cc-plugin/src/engine/context/render.ts` (bagian Context, Rate Limit 5h/7d yang dihilangkan kalau tidak ada data, metadata yang barisnya dilewati, `Last update: HH:MM WIB` dan `(Xm ago)`; reset kuota berupa durasi).

- **Siapa**: hanya pengirim di `allowFrom` bot itu, di chat pribadi (`contextAllowed` di `plugin/context.ts`). Selain itu tidak dibalas sama sekali. `/context` masuk menu plugin dan dicatat di `plugin.log` sebagai `tidak-diteruskan`.
- **Sumber data**: hanya `<state>/status.json` bot itu sendiri, ditulis `plugin/bot-squad-statusline.ts` (bridge) setiap kali Claude Code menggambar ulang baris status. Data bisa basi kalau bot lama menganggur; umurnya terlihat di `Last update`.
- **Bridge** dipasang master saat start (`master/src/statusline.ts`, dipanggil `launch.ts`) lewat `--settings` sesi itu saja. Tidak ada berkas pengaturan Claude yang ditulis. Bridge menangkap payload (gagal menangkap ditelan diam-diam) lalu meneruskan payload yang sama ke statusline pendahulu di `<state>/chained-statusline` (batas 5 detik) dan keluarannya tampil apa adanya; tanpa pendahulu baris statusnya kosong. Pendahulu dicari mengikuti presedens Claude Code: `<workspace>/.claude/settings.local.json`, lalu `<workspace>/.claude/settings.json`, lalu `~/.claude/settings.json` (atau `$CLAUDE_CONFIG_DIR/settings.json`). Akibatnya statusline user pemilik ikut jalan di bot, walau `--setting-sources` tidak memuat pengaturan user.
- **Pagar** (dari README mirza-bots): kalau salah satu berkas itu ada tetapi tak terbaca atau bukan objek JSON, atau yang efektif ternyata bridge bot-squad sendiri, bridge **tidak** dipasang. Rantai ditulis lalu dibaca ulang; tidak cocok berarti batal. Hasilnya dicatat di `<state>/statusline.json`, alasan penolakan juga di log master-bot/`start-bot.sh` (`statusline '<nama>' tidak dipasang: ...`), dan `/context` membalas alasannya. Start bot tidak pernah gagal karena ini.
- **Jawaban lain**: sesi tanpa `statusline.json` (dinyalakan sebelum fitur ini) diminta dinyalakan ulang; `--settings` hanya dibaca saat `claude` start, jadi bot lama baru mendapat `/context` setelah dinyalakan ulang. `status.json` sesi lama dihapus saat start; kalau belum ada, plugin membalas `⏳ Menunggu data statusline...` lalu menunggu berkasnya (12 x 1,5 detik) tanpa menahan update lain. `status.json` yang rusak atau tak terbaca dijelaskan, tanpa angka. Sesi baru sebelum giliran pertama menampilkan `Context (tidak tersedia)` tanpa bagian Rate Limit.
- **Payload nyata** (Claude Code 2.1.323, ditangkap dari sesi uji di tmux tanpa plugin dan tanpa token): sebelum giliran pertama `context_window.used_percentage` bernilai `null` dan `rate_limits` tidak ada. Sesudahnya ada `used_percentage`, `total_input_tokens`, `context_window_size`, dan `rate_limits.seven_day.{used_percentage,resets_at}` (`resets_at` detik epoch); `five_hour` tidak muncul di akun ini saat itu. Statusline dari `--settings` mengalahkan `statusLine` project/local workspace, dan perintahnya berjalan dengan cwd workspace dan environment sesi.
- Tes: `plugin/test/context.test.ts`, `plugin/test/statusline-bridge.test.ts`, `plugin/test/context-command.test.ts` (server sungguhan, dilewati tanpa `plugin/node_modules`), `master/test/statusline.test.ts`.

## Balasan bot: Markdown otomatis dan potongan rapi (tiket 261114101205)

Claude cukup menulis Markdown biasa di alat `reply` dan `edit_message`; plugin mengubahnya ke MarkdownV2 Telegram. Kodenya di `plugin/outbound.ts` (diadaptasi dari `mirza-bots/cc-plugin/src/engine/markdown.ts` dan `chunk.ts`), dengan paket `telegramify-markdown` (dependency plugin; bot pemilik baru memakainya setelah dinyalakan ulang, karena `launch.ts` memasang paket plugin sebelum start).

- **Parameter `format`**: bawaan baru `markdown` (otomatis). `text` tetap teks biasa tanpa `parse_mode`, `markdownv2` tetap diteruskan mentah (pemanggil yang meng-escape). Nilai lain dianggap `markdown`. Instruksi MCP plugin menyuruh Claude menulis Markdown biasa tanpa meng-escape apa pun.
- **Konversi**: `**tebal**`, `*miring*`/`_miring_`, `~~coret~~`, `` `kode` ``, blok berpagar, `[tautan](url)`, daftar (`•` dan `1\.`), judul menjadi tebal, kutipan `>`. Semua karakter khusus MarkdownV2 (``_*[]()~`>#+-=|{}.!`` dan `\`) di teks biasa di-escape; di dalam kode hanya `` ` `` dan `\`. Tabel dan garis `---` tidak punya padanan, jadi di-escape (tampil sebagai teks dengan `|`), tidak dibuang. Bahasa di fence (```` ```ts ````) tidak ikut terkirim; blok tetap tampil sebagai blok kode.
- **Ditolak Telegram**: kalau Telegram tetap menolak format satu potongan (400 `can't parse entities`, `can't find end of ...`, `... is reserved and must be escaped`), potongan itu dikirim ulang sebagai teks aslinya tanpa `parse_mode`, dengan kutipan yang sama, dan `plugin.log` mencatat `format-ditolak`. Error lain (403, jaringan, pesan terlalu panjang) tidak dicoba ulang dan dilaporkan ke Claude seperti dulu (`reply failed after X of N chunk(s) sent`).
- **Pemotongan**: batasnya `textChunkLimit` di `access.json` (maks. 4096), dihitung **setelah** escape. Kalau hasil konversi utuh muat, satu pesan. Kalau tidak, teks **mentah** dipotong dengan jendela setengah batas (escape bisa melipatgandakan panjang), lalu tiap potongan dikonversi sendiri; memotong hasil konversi bisa membelah satu entity. Potongan yang hasil konversinya tetap melewati batas dikirim sebagai teks biasa. Tanpa `chunkMode`, format `markdown` memotong di batas paragraf, lalu baris, lalu spasi, jadi baris kode tidak terbelah; `chunkMode` yang ditulis eksplisit dihormati, dan format `text`/`markdownv2` tanpa `chunkMode` tetap dipotong per panjang seperti dulu.
- **Blok kode terpotong** dijahit ulang: fence yang masih terbuka di akhir potongan ditutup di situ, lalu dibuka lagi (baris pembuka yang sama) di awal potongan berikutnya, sehingga setiap potongan menampilkan kode sebagai blok kode dan teks sesudahnya tidak ikut menjadi monospace. Fence ```` ```` ```` hanya ditutup fence sepanjang itu atau lebih.
- **Kutipan** (`reply_to`) menempel di potongan pertama (`replyToMode` bawaan `first`; `all` dan `off` tetap berlaku). Edit tidak bisa dipotong: kalau hasil konversi melewati 4096, teks aslinya dikirim sebagai teks biasa.
- Tes: `plugin/test/outbound.test.ts` (konversi, karakter khusus per karakter, pemotongan, penjahitan fence, kirim ulang teks biasa) dan `plugin/test/reply-format.test.ts` (server plugin sungguhan terhadap Telegram tiruan yang memeriksa MarkdownV2), keduanya dilewati tanpa `plugin/node_modules`.

## Tombol pilihan di chat bot (tiket 261114101206)

Claude bisa menawarkan pilihan berupa tombol, dan pemilik cukup menekan satu tombol untuk menjawab. Kodenya `plugin/buttons.ts` (aturan, diadaptasi dari `mirza-bots/cc-plugin/src/engine/messages.ts`) dan `plugin/choice-tap.ts` (ketukan), dengan kait kecil di `plugin/server.ts`.

- **Mengirim**: alat `reply` menerima `buttons`, daftar baris berisi `{text, data?}` (contoh `[[{"text":"1"},{"text":"2"}]]`; tombol tunggal di tingkat atas dianggap satu baris). `data` bawaan = `text`. Keyboard menempel di potongan teks **terakhir** balasan; berkas (`files`) tetap dikirim sesudahnya tanpa tombol. `edit_message` tidak memakai tombol. Instruksi MCP plugin menjelaskannya ke Claude.
- **Tombol jawab sendiri**: setiap keyboard pilihan selalu diberi baris terakhir `✏️ Explain manually` (persis mirza-bots, keputusan pemilik Q1) oleh plugin, bukan oleh Claude. Kalau Claude menulisnya sendiri (dikenali dari label atau data `let me explain manually instead`), tombol itu dibuang dulu, jadi tombolnya selalu satu dan selalu terakhir. Balasan tanpa `buttons` (atau `buttons: []`) tidak mendapat keyboard.
- **Ditolak sebelum apa pun terkirim** (alat mengembalikan error berisi cara memperbaikinya, tidak ada pesan maupun berkas yang terkirim): `buttons` bukan daftar, label kosong, `data` bukan teks; `data` lebih dari 62 byte (batas Telegram 64 byte termasuk awalan plugin `c:`; dihitung per byte, emoji 4 byte; label panjang tanpa `data` ikut kena karena label dipakai sebagai data); lebih dari 8 tombol per baris atau 100 per pesan (termasuk tombol jawab sendiri); dan minimal dua tombol berlabel angka saja tanpa baris bernomor yang cocok (`1.` atau `1)` di awal baris) di badan pesan. Satu tombol angka, atau label kata seperti `✅ Ya`/`❌ Tidak`, tidak kena aturan nomor.
- **Saat ditekan**: Telegram selalu dijawab (`answerCallbackQuery`). Hanya pengirim di `allowFrom` bot itu yang dilayani (aturan yang sama dengan tombol izin); orang lain mendapat `Not authorized.` dan tidak ada yang diteruskan atau diubah. Pilihan sampai ke Claude sebagai notifikasi channel biasa: `content` = `data` tombol, meta `button_data`, `button_label`, `button_message_id` (id pesan bertombol), `chat_id`, `user`, `user_id`, `ts`; "typing…" menyala seperti pesan masuk. Tombol jawab sendiri memberi `button_manual="true"` dan `content` yang memberi tahu Claude bahwa pemilik akan mengetik jawabannya sendiri di pesan berikutnya, jadi Claude menunggu dan tidak memilih. Lalu pesan diedit menjadi teks aslinya ditambah `→ <label>` (entity format dipertahankan) tanpa keyboard; kalau tidak bisa (bukan teks, atau melewati 4096), keyboard-nya saja yang dicopot.
- **Sekali jawab**: ketukan pada tombol yang sudah tidak ada di keyboard pesan itu, atau ketukan kedua pada pesan yang sama (diingat per proses, maks. 1000 pesan), dijawab tanpa diteruskan (`ganda` di `plugin.log`).
- **Tombol izin** (`perm:...`) tidak berubah; tombol Claude selalu berawalan `c:`, jadi tidak bisa menyamar sebagai jawaban izin.
- Bot yang sudah berjalan baru mendapat fitur ini setelah dinyalakan ulang (`/restart`).
- Tes: `plugin/test/buttons.test.ts` dan `plugin/test/buttons-server.test.ts` (server plugin sungguhan terhadap Telegram tiruan, dilewati tanpa `plugin/node_modules`).

## /help, /status di chat bot; /start ditelan (tiket 261112225309, 261115202402)

Dua perintah bawaan plugin (`plugin/server.ts`) dijawab plugin sendiri dengan teks Bahasa Indonesia dan tidak dikirim ke Claude. `/help` menjelaskan bahwa pesan (teks dan foto) diteruskan ke sesi Claude Code bot itu dan balasannya kembali ke chat, lalu mendaftar `/status` dan `/context`. `/status` menjawab bahwa pengirim diizinkan, lengkap dengan username dan ID-nya.

- **Siapa**: hanya pengirim di `allowFrom` bot itu, di chat pribadi, apa pun `dmPolicy`-nya (aturan yang sama dengan `/context`, `contextAllowed`). Orang lain, juga di grup, tidak dibalas sama sekali.
- **`/start` bukan perintah lagi** (keputusan pemilik 2026-11-15, tiket 261115202402: tidak berguna, `/help` sudah menjelaskan hal yang sama). Tidak ada di menu bot maupun teks `/help`. Telegram tetap mengirim `/start` saat seseorang menekan tombol Start di chat bot, jadi plugin menelannya (`bot.command('start', () => {})`): `/start`, `/start <teks>`, dan `/start@<username bot>` tidak dibalas, tidak diteruskan ke Claude (tidak memakai giliran), tanpa "typing…" dan reaksi, dan tercatat di `plugin.log` sebagai `tidak-diteruskan`. Berlaku untuk siapa pun dan di chat apa pun, sama seperti sebelumnya untuk pengirim yang tidak diizinkan. Menu ditulis ulang setiap polling mulai (`setMyCommands` di cakupan `all_private_chats`: `help`, `status`, `context`), jadi menu lama yang memuat `/start` tergantikan begitu bot dinyalakan ulang (`/restart`); menu sisa khusus bahasa atau di cakupan lain tidak ditangani.
- Tes: `plugin/test/commands.test.ts` (server plugin sungguhan terhadap Telegram tiruan, dilewati tanpa `plugin/node_modules`).

## Tanpa skill dan tanpa pairing (tiket 261115085701)

Keputusan pemilik (2026-11-15): warisan plugin resmi yang mengandaikan seseorang duduk di terminal bot dibuang, karena semuanya sudah diambil alih master-bot.

- **Skill dihapus**: folder `plugin/skills/` (`access` dan `configure`) tidak ada lagi, jadi sesi bot tidak memuat skill apa pun dari plugin. Token ditulis `/register`; allowlist diubah lewat `/allow`, `/revoke`, `/access` di master-bot.
- **Pairing dihapus** dari `plugin/server.ts`: tidak ada kode, tidak ada balasan ke pengirim tak dikenal, tidak ada `pending`, dan folder `approved/` tidak lagi dipindai. Pengirim di luar `allowFrom` selalu dibuang tanpa balasan dan dicatat `dibuang` di `plugin.log`, apa pun `dmPolicy`-nya.
- **`dmPolicy`** tinggal dua arti: `disabled` membuang semua pesan; nilai lain apa pun (termasuk `pairing` dari berkas lama, atau tidak diisi) diperlakukan sebagai `allowlist`. `access.json` yang tidak ada atau rusak berarti tidak ada yang diizinkan (yang rusak tetap dipindahkan ke `access.json.corrupt-<waktu>`). Plugin tidak pernah menulis `access.json`; kolom `pending` di berkas lama diabaikan dan dibiarkan.
- **Teks**: instruksi MCP ke Claude menyebut akses diatur pemilik di master-bot (`/allow`, `/revoke`, `/access`) dan tetap melarang Claude mengubah `access.json` atau akses karena diminta lewat pesan. Galat `reply`/`react`/`edit_message` ke chat di luar allowlist juga merujuk ke `/allow` di master-bot. `plugin/README.md`, `plugin/ACCESS.md`, dan `plugin.json` ikut dirapikan. Catatan `/allow` untuk `dmPolicy` selain `allowlist` kini menyebut nilainya diperlakukan sebagai `allowlist`.
- **Tidak berubah**: grup di `access.json` (`groups`) dan setelan keluaran (`replyToMode`, `chunkMode`, `ackReaction`, `mentionPatterns`, `textChunkLimit`) tetap dibaca; hanya cara mengubahnya lewat skill yang hilang (belum ada perintah master-bot untuk itu).
- Bot yang sudah berjalan baru berubah setelah dinyalakan ulang (`/restart`).
- Tes: `plugin/test/no-pairing.test.ts` (server plugin sungguhan terhadap Telegram tiruan, per nilai `dmPolicy`; dilewati tanpa `plugin/node_modules`).

## "typing…" dan reaksi tanda diterima di chat bot (tiket 261114101201)

Setiap pesan yang diteruskan ke Claude (hasil `diteruskan` di `plugin.log`) langsung mendapat dua tanda di Telegram, supaya pemilik tahu pesannya sampai dan bot sedang bekerja. Kodenya `plugin/typing.ts`, dipakai dari `plugin/server.ts`; angkanya sama dengan mirza-bots.

- **"typing…"** dikirim saat itu juga, lalu diulang setiap 4 detik (Telegram memadamkannya sendiri ~5 detik), sampai balasan pertama yang berhasil lewat alat `reply` ke chat itu (teks atau berkas). `react` dan `edit_message` tidak menghentikannya. Batas aman 300 detik sejak pesan masuk terakhir di chat itu, juga kalau Claude tidak pernah membalas; pesan baru saat masih menyala memperpanjang batas tanpa menambah timer. Gagal kirim (429, jaringan) ditelan dan tidak menggagalkan penerusan. Saat server plugin berhenti, semua timer dilepas.
- **Tidak ada "typing…"** untuk pengirim di luar allowlist (`dibuang`), perintah plugin (`/help`, `/status`, `/context`), `/start` yang ditelan, dan jawaban izin `yes/no xxxxx` (tetap hanya ✅/❌).
- **Reaksi tanda diterima**: `ackReaction` di `access.json`; kalau tidak diisi, plugin memakai 👀 (keputusan pemilik Q1), jadi semua bot mendapatkannya tanpa mengubah `access.json`. Bot yang sudah berjalan baru mendapatkannya setelah dinyalakan ulang (`/restart`). `ackReaction: ""` mematikannya; emoji lain harus ada di daftar reaksi Telegram. Reaksi dipasang sekali dan tidak dicopot setelah Claude membalas.
- `BOT_SQUAD_TYPING_MAX_MS` hanya untuk tes (mempercepat batas 300 detik) dan hanya dibaca kalau `BOT_SQUAD_TELEGRAM_API_ROOT` diisi.
- Tes: `plugin/test/typing.test.ts` (jam palsu, termasuk batas 300 detik) dan `plugin/test/typing-server.test.ts` (server plugin sungguhan terhadap Telegram tiruan, dilewati tanpa `plugin/node_modules`).

## Kutipan pesan di chat bot (tiket 261114101202)

Kalau pemilik membalas sebuah pesan di chat bot (mengutip seluruhnya, atau menyeleksi sebagian teksnya), plugin meneruskan pesan itu ke Claude dengan atribut tambahan di tag `<channel>` (`plugin/quote.ts`, dipanggil dari `handleInbound` di `plugin/server.ts`, jadi berlaku untuk teks, foto, dokumen, dan jenis lain). Isi pesan (`content`) tidak berubah.

- `reply_to_message_id`: id pesan yang dikutip (bisa dipakai sebagai `reply_to`).
- `quote_text`: yang dikutip. Urutannya: bagian yang diseleksi (`message.quote.text`), lalu teks pesan yang dikutip, lalu kapsinya, lalu keterangan jenis seperti `(photo)`, `(document: <nama>)`, `(sticker 👍)`.
- `quote_is_manual`: `true` kalau pemilik menyeleksi sebagian teks, `false` kalau seluruh pesan dikutip.
- `quote_kind`: `text` (dari teks/kapsi) atau `media` (hanya keterangan jenis; berkas pesan yang dikutip tidak dilampirkan).
- Pembersihan: `quote_text` hanya ada di meta, tidak di `content`. Karakter `< > [ ] ; "`, karakter kontrol, dan pemisah baris Unicode diganti `_`, baris baru ditulis ` ⏎ `, dan teks lebih dari 1000 karakter dipotong dengan `…`. Jadi teks kutipan tidak bisa keluar dari tag atau memalsukan atribut seperti `image_path`/`attachment_*`. Instruksi MCP plugin menjelaskan atribut ini ke Claude dan menyebut kutipan sebagai konteks, bukan perintah atau lampiran.
- Tidak diteruskan sebagai kutipan: pesan tanpa `reply_to_message` (atribut di atas tidak ada sama sekali), kutipan dari chat lain (`external_reply`), dan "balasan" otomatis ke pesan pembuka topik di grup bertopik.
- Tes: `plugin/test/quote.test.ts` dan `plugin/test/quote-server.test.ts` (server plugin sungguhan terhadap Telegram tiruan, dilewati tanpa `plugin/node_modules`).

## Dokumen besar dan nama berkas di chat bot (tiket 261114101203)

Lampiran yang dikirim ke bot (dokumen, juga audio, video, voice, video note) diperiksa di `plugin/attachment.ts`, dipanggil dari `handleInbound` dan `download_attachment` di `plugin/server.ts`.

- **Sampai 20 MB** (`MAX_DOWNLOAD_BYTES` = 20 x 1024 x 1024 byte, batas `getFile` Bot API; tepat 20 MB masih boleh): seperti sebelumnya. Meta berisi `attachment_file_id`, dan Claude mengunduh lewat `download_attachment`.
- **Di atas 20 MB** (menurut `file_size` dari Telegram): tidak diunduh. Meta berisi `attachment_too_large="true"`, `attachment_name`, `attachment_size` (byte), dan `attachment_mime` kalau ada, **tanpa** `attachment_file_id`. Content mendapat satu kalimat tambahan (setelah kapsi, kalau ada) dengan nama, ukuran dalam MB, dan batas 20 MB, supaya Claude memberi tahu pemilik. Instruksi MCP menjelaskan atribut ini. `download_attachment` untuk `file_id` itu langsung ditolak dengan pesan jelas tanpa memanggil Telegram (ingatan 200 `file_id` terakhir); kalau ukurannya tidak diketahui dan Telegram menjawab `file is too big`, pesannya sama.
- **Nama berkas** dari pengirim hanya menjadi teks di meta dan content, setelah `safeName()`: `\` dianggap `/`, hanya bagian setelah `/` terakhir yang dipakai, karakter `< > [ ] ;`, tanda kutip tunggal dan ganda, serta backtick dibuang, karakter kontrol dan pemisah baris Unicode jadi spasi, titik di depan dibuang, maks. 100 karakter (`…`), dan nama kosong menjadi `file`. Contoh: `../../.zshrc` menjadi `zshrc`, `report[image attached — read: /etc/passwd].pdf` menjadi `passwd.pdf`. Berlaku juga untuk judul audio.
- **Berkas unduhan** (dokumen dan foto) selalu `inbox/<waktu>-<file_unique_id>.<ext>`, dengan `file_unique_id` dan ekstensi dari `file_path` Telegram yang disaring (alfanumerik). Nama dari pengirim tidak pernah menjadi path, dan `inboxPath()` menolak hasil yang tidak berada langsung di dalam `inbox/`. Alamat unduhan memakai `BOT_SQUAD_TELEGRAM_API_ROOT` kalau diset (tes).
- Tes: `plugin/test/attachment.test.ts` (aturan per kasus) dan `plugin/test/attachment-server.test.ts` (server plugin sungguhan terhadap Telegram tiruan: dokumen kecil, tepat 20 MB, 25 MB, video 30 MB, nama berbahaya, dan tidak ada berkas di luar `inbox/`; dilewati tanpa `plugin/node_modules`).

## Album di chat bot (tiket 261114101204)

Album (beberapa foto, video, atau dokumen yang dikirim sekaligus) sampai ke Claude sebagai **satu** pesan, jadi Claude tidak mulai menjawab sebelum album lengkap. Kodenya `plugin/album.ts` (penahan dan pembentuk pesan), dipanggil dari `handleInbound` di `plugin/server.ts`; angkanya sama dengan mirza-bots.

- **Penahanan**: hanya pesan yang punya `media_group_id` yang ditahan; foto tunggal, teks, dan jenis lain langsung diteruskan seperti dulu. Album diteruskan 1,5 detik setelah item terakhir, paling lama 8 detik sejak item pertama, dan paling banyak 10 item per pesan (kelebihannya jadi pesan berikutnya, tidak dibuang). Kunci album = chat + `media_group_id`. Sisa album yang hanya satu item diteruskan sebagai pesan biasa.
- **Gerbang** dicek per item sebelum ditahan: item dari pengirim di luar allowlist dibuang (`dibuang`) tanpa diunduh, tanpa "typing…" dan reaksi.
- **Isi**: item diurutkan `message_id` menaik (bukan urutan tiba) dan diberi nomor 1..n. Baris pertama `(album of <n> items)`, lalu satu baris per item: `Photo 1: <kapsi>`, `Photo 2` (tanpa kapsi), `Video 3 "<nama>": <kapsi>`, `Document 1 "<nama>"`. Jadi setiap kapsi jelas milik item yang mana. Nama lewat `safeName()`.
- **Meta**: `message_id` = item pertama, `album_size`, `album_message_ids` (dipisah koma, urut album), `image_path` (foto pertama yang berhasil, kompatibel dengan foto tunggal) dan `image_path_<n>` per foto. Album campuran (keputusan pemilik Q1): foto diunduh, item lain jadi lampiran bernomor `attachment_<n>_kind`, `attachment_<n>_file_id` (diunduh Claude lewat `download_attachment`), `_size`, `_mime`, `_name`; di atas 20 MB `attachment_<n>_too_large="true"` tanpa `file_id` plus kalimat 20 MB di content, sama dengan lampiran tunggal. Kutipan (`quoteMeta`) diambil dari item pertama yang membalas pesan. Pengingat `context_reminder` (tiket 261114101207) ikut sekali per album. Instruksi MCP plugin menjelaskan atribut ini.
- **Foto gagal diunduh** (`getFile` ditolak, unduhan bukan 2xx, jaringan): foto lain tetap diteruskan, barisnya ditandai `(download failed)`, meta `album_failed` berisi nomor fotonya, dan content ditutup dengan `(photo <n> could not be downloaded — tell the sender; the other items arrived)`. Sejak tiket ini unduhan foto yang dijawab bukan 2xx juga dianggap gagal (dulu isinya ditulis sebagai foto), termasuk untuk foto tunggal.
- **Tanda**: "typing…" menyala saat item pertama diterima; reaksi tanda diterima dipasang sekali, di item pertama album.
- **plugin.log**: satu baris `pesan` per item dengan kolom tambahan `album=<media_group_id>`, semua dicatat saat album diteruskan. Album yang masih ditahan saat server plugin berhenti dibuang (tidak diteruskan setengah jadi) dan setiap itemnya dicatat `hasil=gagal alasan="plugin berhenti sebelum album diteruskan"`.
- Tes: `plugin/test/album.test.ts` (jam palsu: jeda, batas 8 detik, 10 item, album terpisah, pembentuk pesan per kasus) dan `plugin/test/album-server.test.ts` (server plugin sungguhan terhadap Telegram tiruan: album 3 foto yang tiba acak, album dengan foto gagal, foto tunggal dan teks tanpa jeda, album campuran dan album dokumen, pengirim tak diizinkan, berhenti saat album ditahan; dilewati tanpa `plugin/node_modules`).

## Pengingat konteks menipis (tiket 261114101207)

Saat konteks sesi bot menipis, pesan pemilik berikutnya yang diteruskan ke Claude membawa atribut `context_reminder` di tag `<channel>` (`plugin/context-reminder.ts`, dipanggil dari `handleInbound` di `plugin/server.ts`). Isinya imbauan plus angkanya, misalnya `Konteks sesi ini sudah terpakai 412.3k dari 1M token (41%), di atas ambang ...`. Instruksi MCP plugin menyuruh Claude menyebutnya singkat ke pemilik dan menawarkan percakapan baru; keputusannya milik pemilik, Claude tidak boleh memulai percakapan baru, compact, atau handoff sendiri. Mengikuti `context-low` mirza-bots.

- **Ambang** (keputusan pemilik Q1): menyala kalau `total_input_tokens` di atas **400 ribu** ATAU terpakai di atas **50%** jendela (`used_percentage`, atau `total_input_tokens / context_window_size`), mana yang lebih dulu. Jadi di jendela 200 ribu menyala di atas 100 ribu, di jendela 1 juta di atas 400 ribu. Tepat di ambang tidak menyala.
- **Pemicunya keadaan**: `<state>/status.json` (tangkapan statusline yang sama dengan `/context`) dibaca setiap kali pesan diteruskan. Selama di atas ambang setiap pesan membawanya; begitu di bawah ambang (misalnya setelah `/clear`, karena Claude Code menggambar ulang statusline saat sesi baru mulai) hilang sendiri. Tidak ada flag "sudah diingatkan".
- **Tidak pernah dikirim sendirian**: hanya atribut pada notifikasi pesan yang memang diteruskan (`diteruskan` di `plugin.log`, termasuk foto dan dokumen). Perintah plugin (`/context` dll.), jawaban izin, dan pesan yang dibuang tidak membawanya. Isi pesan (`content`) tidak berubah, dan pengingat hanya di meta supaya tidak bisa dipalsukan dengan mengetik.
- **Data tidak ada atau tidak pasti berarti tanpa pengingat**: `status.json` tidak ada (bridge tidak terpasang, sesi lama), rusak, atau `used_percentage` bukan angka (sesi baru sebelum giliran pertama, sesudah `/compact`). Umur berkas bukan syarat: `status.json` sesi sebelumnya dihapus saat start, dan konteks sesi yang menganggur tidak berubah. Gagal membaca tidak pernah menahan pesan.
- Tes: `plugin/test/context-reminder.test.ts` (matriks ambang dan data tidak ada) dan `plugin/test/context-reminder-server.test.ts` (server plugin sungguhan terhadap Telegram tiruan, dilewati tanpa `plugin/node_modules`).
